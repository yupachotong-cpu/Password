# โปรแกรมตรวจสอบรหัสผ่านตามแนวทาง OWASP (JavaScript & Rust)

โปรเจกต์ปรับปรุงโปรแกรมตรวจสอบรหัสผ่านให้เป็นไปตามคำแนะนำด้านความปลอดภัยของ **OWASP** โดยพัฒนาขึ้นใหม่เป็น 2 เวอร์ชัน ได้แก่ **JavaScript (Node.js)** และ **Rust** เพื่อเปรียบเทียบการทำงานและมาตรฐานความปลอดภัยของทั้งสองภาษา

## 1. วิธีติดตั้ง วิธีรัน และวิธีสแกน Semgrep

### ข้อกำหนดเบื้องต้น (Prerequisites)
* **Node.js** เวอร์ชัน 18 ขึ้นไป
* **Rust & Cargo** ติดตั้งผ่าน `rustup` (สำหรับ Windows แนะนำให้ตั้งค่า Toolchain เป็น `stable-x86_64-pc-windows-gnu` หรือติดตั้ง Microsoft C++ Build Tools)
* **Semgrep** สำหรับตรวจสอบความปลอดภัยของซอร์สโค้ด (Static Application Security Testing)

### วิธีติดตั้งเครื่องมือ
1. **ติดตั้ง Semgrep:**
   ```bash
   pip install semgrep
   ```
   *(หรือบน Windows สามารถติดตั้งผ่าน `winget install Semgrep.Semgrep`)*

2. **ตั้งค่า Toolchain ของ Rust (กรณีรันบน Windows แล้วไม่พบ `link.exe`):**
   ```bash
   rustup toolchain install stable-x86_64-pc-windows-gnu
   rustup default stable-x86_64-pc-windows-gnu
   ```

### วิธีรันโปรแกรม

* **รันเวอร์ชัน JavaScript (Node.js):**
  ```bash
  cd js-version
  node index.js
  ```

* **รันเวอร์ชัน Rust:**
  ```bash
  cd rust-version
  cargo run
  ```

### วิธีสแกนช่องโหว่ด้วย Semgrep
เข้าไปที่โฟลเดอร์หลักของโปรเจกต์ (`password-validator/`) แล้วรันคำสั่ง:
```bash
semgrep scan --config auto
```
*(หรือระบุชุดกฎเฉพาะภาษา: `semgrep scan --config p/javascript --config p/rust`)*

## 3. สรุปผล Semgrep และคำอธิบาย

* **คำสั่งที่ใช้ตรวจสอบ:** `semgrep scan --config auto`
* **ผลลัพธ์การสแกน:** พบช่องโหว่ (Findings) จำนวน **0 รายการ** (0 Errors / 0 Warnings) ทั้งในไฟล์ `js-version/index.js` และ `rust-version/src/main.rs`
* **คำอธิบายเชิงความปลอดภัย:**
  1. **ป้องกันข้อมูลรั่วไหล (No Sensitive Data Exposure):** โค้ดไม่มีการสั่งพิมพ์ (`console.log` หรือ `println!`) ตัวแปร `password` ออกทางหน้าจอซ้ำ และไม่มีการใช้ไลบรารีจัดการไฟล์ (`fs` / `std::fs`) เพื่อบันทึกรหัสผ่านลงดิสก์
  2. **ไม่มีความเสี่ยงด้าน ReDoS:** การตรวจสอบความยาวรหัสผ่านใช้วิธีนับจำนวนอักขระโดยตรง ไม่ใช้ Regular Expression ที่ซับซ้อน จึงปลอดภัยจากการโจมตีแบบ Regular Expression Denial of Service
  3. **ไม่มีการฝังข้อมูลลับในโค้ด (No Hardcoded Secrets):** ซอร์สโค้ดและไฟล์ตั้งค่าทั้งหมดไม่มีรหัสผ่านจริง ข้อมูลส่วนตัว หรือ API Key ฝังอยู่

## 4. Prompt ที่ใช้กับ AI และตัวอย่างจุดที่กลุ่มตรวจสอบ/แก้ไขจากโค้ด AI

### Prompt ที่ใช้กับ AI
> *"จากโจทย์ปรับปรุงโปรแกรมตรวจสอบรหัสผ่านตามแนวทาง OWASP ให้เขียนโค้ด 2 เวอร์ชันคือ JavaScript (Node.js) และ Rust โดยรับ username และ password ความยาวขั้นต่ำ 15 ตัวอักษร ไม่บังคับชนิดอักขระ อนุญาตช่องว่างหัวท้ายและ Unicode รองรับความยาวอย่างน้อย 64 ตัวอักษรโดยไม่ตัดทอน และไม่แสดงรหัสผ่านซ้ำหรือไม่บันทึกลงไฟล์"*

### ตัวอย่างจุดที่กลุ่มตรวจสอบและปรับแก้ไขจากโค้ด AI

1. **การรักษาช่องว่างหัวท้ายใน Rust (`trim` vs `trim_end_matches`):**
   * **ปัญหาที่พบจากการตรวจสอบ:** คำสั่ง `io::stdin().read_line()` ใน Rust จะเก็บอักขระขึ้นบรรทัดใหม่ (`\r\n` บน Windows) ติดมาท้ายข้อความ หากใช้เมธอด `.trim()` ทั่วไป จะเผลอลบช่องว่าง (Spacebar) ที่ผู้ใช้ตั้งใจใส่ไว้ด้านหน้าหรือด้านหลังรหัสผ่าน ซึ่งผิดข้อกำหนดข้อที่ 4
   * **การแก้ไข:** ตรวจสอบและเปลี่ยนมาใช้ `.trim_end_matches(&['\r', '\n'][..])` เพื่อตัดเฉพาะปุ่ม Enter และรักษาช่องว่างหัวท้ายของรหัสผ่านไว้ครบถ้วน

2. **ความถูกต้องในการนับความยาวอักขระ Unicode:**
   * **ปัญหาที่พบจากการตรวจสอบ:** ใน JavaScript การใช้ `password.length` ปกติจะนับอีโมจิ 1 ตัวเป็น 2 หน่วย (UTF-16 code units) ส่วนใน Rust การใช้ `password.len()` จะนับเป็นจำนวน Byte (เช่น ภาษาไทย 1 ตัวอักษร = 3 bytes) ทำให้นับความยาวรหัสผ่านคลาดเคลื่อน
   * **การแก้ไข:** ใช้ `[...password].length` ใน JavaScript และใช้ `password.chars().count()` ใน Rust เพื่อให้นับจำนวนตัวอักษร Unicode ตามจริง

3. **การจัดการไฟล์ตั้งค่าโปรเจกต์ (`package.json` และ `Cargo.toml`):**
   * **ปัญหาที่พบจากการตรวจสอบ:** พบข้อผิดพลาด `ERR_INVALID_PACKAGE_CONFIG` ใน Node.js เมื่อมีไฟล์ `package.json` เปล่า และพบ `could not find Cargo.toml` ใน Rust เมื่อสร้างโฟลเดอร์เอง
   * **การแก้ไข:** ลบไฟล์ `package.json` ที่ไม่สมบูรณ์ออก (เนื่องจากใช้โมดูลมาตรฐาน `readline` ของ Node.js) และรัน `cargo init` เพื่อสร้างไฟล์ `Cargo.toml` ที่ถูกต้อง รวมถึงสร้าง `.gitignore` เพื่อไม่ให้โฟลเดอร์ `target/` ถูกอัปโหลดขึ้น Git
